# 项目专属运维面板 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在同一个 compose 堆栈内新增一个项目专属运维面板，让用户通过 `http://<宿主IP>:8080` 完成参数调整、调度、运行、日志、产物、IP 库和发布运维，且面板保存与手工编辑 `.env` 完全同源。

**Architecture:** 两个容器（`scanner` + `panel`）、单镜像、单 compose 项目。`.env` 是唯一配置源：扫描器每轮重新读取 `/project/.env`，面板原子改写同一个文件；显式环境变量优先于 `.env`。panel 是独立 FastAPI 服务，通过挂载的 docker.sock 只操作本项目扫描容器；前端 Vue SPA 由后端托管。

**Tech Stack:** Python 3.13、FastAPI 0.162、uvicorn 0.54、docker SDK 7.2、Pydantic 2.14、sse-starlette 3.6、Argon2id、SQLite、Vue 3.5、TypeScript 5.9、Vite 8、Element Plus 2.14、Pinia、Vue Router、pytest 9、Vitest 5、Node 24、Alpine。

**Spec:** `docs/superpowers/specs/2026-11-03-ops-panel-design.md`

**Status:** 已归档，待开发（2026-11-03）

## Global Constraints

- 面板是默认、首选的运维入口；CLI、`docker compose run` 与手工编辑 `.env` 仅作备用/应急。
- `.env` 是唯一配置源；读取优先级：显式环境变量 > `.env` > schema 默认值；空值视为未设置。
- compose 不再使用 `env_file`；`.env` 仍用于 `${IMAGE_NAME}` / `${PANEL_PORT}` 等插值。
- scanner 挂载 `./:/project:ro`，panel 挂载 `./:/project`；`DOTENV_PATH=/project/.env`。
- 单镜像、双入口；`scanner` 与 `panel` 使用同一个 `${IMAGE_NAME}:${IMAGE_TAG}`。
- 面板只操作本项目扫描容器；前端不得传容器 ID 或任意文件路径。
- `PUID` / `PGID` / `TZ` / `RUN_ON_START` 保存后需重启扫描容器；`IMAGE_*` / `CONTAINER_NAME` / `PANEL_*` 只读。
- `GIT_TOKEN` 与带认证信息的代理 URL 只写不读；diff、审计、日志脱敏。
- UI 文案为简体中文；危险操作二次确认。
- 版本以 Spec §9 为准，实现时用 lockfile 锁定；运行期不用 `latest`。
- 技术栈冻结：FastAPI/uvicorn/docker SDK/Pydantic/SQLite；Vue 3 + TS + Vite +
  Element Plus + Pinia + Vue Router；不混用第二套 UI 框架、状态库或 ORM。
- 若团队明确要求 React，必须在 Task 16 前整体切换并在计划中记录 ruling；
  不允许前端两套并存。
- 依赖升级单独 PR，跑完整测试与 Compose/E2E 门禁；功能开发中途不升大版本。
- 不引入通用 Docker 管理接口、Web 终端或任意命令执行。

## Review Focus

1. 手工编辑 `.env` 出现 CRLF、重复键、引号、行内注释或不支持的语法时，解析结果必须与 Compose 常用语义一致或明确失败，不能静默读错。
2. 面板保存与宿主同时编辑 `.env` 时，必须 409 而不是丢失一方的修改。
3. 扫描容器停止、重启或 docker.sock 不可用时，面板仍可访问，操作返回清晰错误，SSE 能重连。
4. 产物文件名、IP 库备份名等输入必须阻止路径穿越，不能读取 `.env`、`panel.db` 或宿主任意文件。
5. cron 非法或 `apply-config.sh` 失败时，必须保留旧 crontab 并显示错误，不能让调度器静默停摆。
6. 保存成功但扫描器仍读到旧值时，界面必须显示 `verification.status="mismatch"` 与差异，不能显示“已生效”。
7. 接口失败、无产物、无日志、无轮次时，界面必须显示错误/空状态与重试，不能用示例或缓存数据冒充当前状态。
