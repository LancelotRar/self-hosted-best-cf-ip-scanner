# 候选地址库

[← 返回首页](../README.md) · [配置手册](configuration.md)

扫描的输入完全来自候选地址库。它存在面板的数据库里，只能在面板
「参数调整 · 自定义 IP 库」里查看和编辑，改完保存后下一轮扫描自动生效，
不需要重启容器或重建镜像。宿主目录里不会出现任何地址库文件。

首次启动时面板会导入镜像内置的默认库；从旧版本（`./data/ip-library.txt`）升级时，
首次启动会自动把旧文件导入数据库，之后以数据库为准。

## 两个列表

面板「参数调整 · 自定义 IP 库」里有两个互不相干的列表：

### 1. 内置 IP 库（参与采样）

```text
104.16.0.0/13          # 网段：合并后按采样步长抽代表 IP
104.17.3.3             # 单个 IP：等价 /32，同样要过采样
# 172.68.0.0/24         # 行首 # = 注释，不参与扫描
```

这里只是**候选池**。网段会先合并成连续区间，再按 `SAMPLE_STRIDE`（默认 256）
每个窗口抽 1 个代表 IP——所以写进去的单个 IP 不保证一定被抽中。
带端口的条目无法在采样后保留端口，**不属于这个列表**，请放到下面的固定保留。

### 2. 固定保留（不参与扫描）

```text
1.2.3.4:443#手动添加     # 带端口 + 自定义标注
1.2.3.5                  # 省略端口时按 443
```

这些条目不做 TCP 探测、不做端点校验、不做机房映射，**单独生成一个产物文件**
（文件名由 `PINNED_OUTPUT_NAME` 决定，默认 `PINNED.txt`），不写入 `GLOBAL{N}.txt`
或国家列表，也不影响排名。`#` 之后的内容原样保留，所以可以写自己的备注。
列表清空时该文件会被删除，避免上一轮的内容一直被发布出去。

空行、`#` 开头的行、`cidr` / `ip` 这类表头行会被跳过。无法解析的行不会中断扫描，
只在日志里计数。

## 排除网段

**用注释，不要物理删除。** Cloudflare 的路由与 EIV 归属会变化，注释掉可以一行恢复：

```text
# 172.68.0.0/24   实测 TCP 不可达，2026-10 暂时移出
# 104.22.0.0/24    无合格产出
```

建议同时写明依据与日期，便于回溯。

注释行是**真的从候选里扣掉**，可以只排除某个大段的子集：有效库里有
`104.16.0.0/13`、同时注释 `# 104.16.0.0/14` 时，参与采样的只剩
`104.20.0.0/14`（26 万个地址），而不是整个 /13。

- 扣减在合并之后进行，所以注释一个与有效库不相交的网段不会改变任何数字；
- 「当前 IP 总量」显示的就是扣减之后的地址数。

## 采样关系

- 网段条目会先合并成连续地址区间（重叠、首尾相接的会被合并），再按地址网格每
  `SAMPLE_STRIDE`（默认 256，即一个 `/24`）抽 1 个代表 IP。
- 固定保留列表**完全不进入**这段逻辑：不采样、不探测、不排名。
- 因此库越精简，单轮越快；想覆盖更密就减小 `SAMPLE_STRIDE`；想少扫就把对应行注释掉——
  候选量完全由库决定，没有额外的总量上限。

## 机房映射

机房映射是「边缘机房代码 → 国家代码」的固定表（如 `HKG` → `HK`），决定订阅行里的
国家与国旗。它和地址库一样存在数据库里，宿主不可见。结构是扁平 JSON：

```json
{
  "HKG": "HK",
  "NRT": "JP",
  "SIN": "SG"
}
```

- 缺映射不会报错，订阅行会回退显示机房代码（如 `#HKG`）。
- 在面板「参数调整 · 机房映射」里以表格增删改；页面会提示非必要无需编辑。
- 调试时可在 `.env` 里设 `SKIP_LOCATIONS=true` 跳过映射。

## 生效与验证

```bash
docker compose run --rm scan-once          # 立刻跑一轮（每轮都重新读地址库）

# 看解析结果：行数 / 可解析网段数 / 非法行 / 首末条
docker compose exec scanner /usr/local/bin/doctor.sh | sed -n '/===== IP 库/,/===== 磁盘/p'

# 看读取汇总
docker compose logs | grep "候选地址库"
```

面板「参数调整 · 自定义 IP 库」标题右侧会显示 **参与探测 / 跳过** 两个数字，
保存后立即反映在数据库里。

## 权限

地址库写在命名卷 `ip-data` 里，属主是 `PUID:PGID`（默认 `1000:1000`）。宿主机
当前用户不是 1000 时，把 `.env` 的 `PUID` / `PGID` 改成 `id -u` / `id -g`。

## 默认库与内容建议

- 默认库 = **Cloudflare 官方 IPv4 段**（<https://www.cloudflare.com/ips-v4>）**原样收录**：
  15 个网段，不展开成 `/24`、不删改、不排序。按 `SAMPLE_STRIDE=256` 采样后约 5956 个候选。
- 官方段之外的少量 `/24` 可以自行追加，但要写清依据。
- 不要引入 `1.0.0.0/24`、`1.1.1.0/24`：这是 CF DNS 解析器地址，扫描必然失败。
- 不要引入第三方「反代 IP」列表：多为 VPS 反代，ASN 不属于 AS13335，带宽与存活不可控。
- 想换用其它库文件：改 `.env` 的 `LIBRARY_FILE`，它决定数据库内容投影到卷里的文件名。
  日常维护只需要在面板里改内容。
